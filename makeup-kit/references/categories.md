# 妆匣与推荐共用的品类与特点词表

妆匣输入、目标需求和推荐中的具体商品使用**同一套标准品类与同一套特点维度**。

**权威来源在代码里**：`lib/kit/categories.ts`（品类）与 `lib/kit/attributes.ts`（维度与取值）。本文件是它的可读说明；两者不一致时以代码为准（有测试钉住它们不许漂）。改词表要同时改两边。

## 标准品类

一级中文名称沿用美妆产品仓库的 `CATEGORY_OPTIONS`（由 `lib/kit/categories.ts` 派生）。注意「眉笔」这个一级显示名称在内部代表**整个眉部产品组**。

| categoryId | 标准一级品类 | 具体类型 / 常见输入别名 | 推荐表的区域示例 |
| --- | --- | --- | --- |
| `base` | 底妆 | 粉底、粉底液、粉底霜、气垫、有色底妆、妆前乳 | 全脸底妆 |
| `concealer` | 遮瑕 | 遮瑕液、遮瑕膏、遮瑕盘、校色 | 全脸或局部遮瑕 |
| `setting` | 定妆 | 散粉、蜜粉、定妆粉饼、定妆喷雾 | 全脸或局部定妆 |
| `brow` | 眉笔 | 眉粉、染眉膏、眉胶、眉毛定型产品 | 眉毛 |
| `eyeshadow` | 眼影 | 单色眼影、眼影盘、眼影液、眼影膏 | 眼窝 / 眼影 |
| `eyeliner` | 眼线 | 眼线笔、眼线液、眼线胶、眼线膏 | 眼线 |
| `mascara` | 睫毛膏 | 睫毛打底、纤长 / 浓密 / 卷翘睫毛膏 | 睫毛 |
| `blush` | 腮红 | 腮红粉、腮红膏、腮红液、腮红盘 | 面颊 |
| `contour` | 修容 | 修容粉、修容棒、阴影、古铜产品 | 鼻部 / 轮廓 |
| `highlight` | 高光 | 高光粉、高光棒、高光液 | 颧骨或相关提亮区域 |
| `lip` | 唇妆 | 口红、唇膏、唇釉、唇蜜、唇彩、唇线笔 | 嘴唇 |
| `tools` | 工具 | 刷具、海绵、粉扑、睫毛夹、假睫毛、睫毛胶 | 按实际使用区域 |

## 特点维度

需求侧（妆容目标）与能力侧（已有单品）必须落在同一组维度与取值上，否则比对只剩自由发挥。

| categoryId | 决定性维度 |
| --- | --- |
| `base` | 遮盖力 清透/中等/高 · 妆效 雾面/半哑光/水光 · 持妆 一般/持久 |
| `concealer` | 遮盖力 清透/中等/高 · 妆效 雾面/水光 |
| `setting` | 妆效 哑光/微光 · 控油 弱/中/强 |
| `brow` | 色系 灰/棕/黑/红棕 · 形态 笔/粉/膏 |
| `eyeshadow` | 色系 · 妆效 哑光/珠光/大闪 · 显色度 清透/中等/浓郁 |
| `eyeliner` | 色系 黑/棕/其他 · 形态 笔/液/胶 · 防水 是/否 |
| `mascara` | 结构 纤长/浓密/卷翘 · 防水 是/否 |
| `blush` | 色系 · 质地 粉/膏/液 · 显色度 清透/中等/浓郁 |
| `contour` | 色温 冷/暖/中性 · 质地 粉/膏 |
| `highlight` | 色温 冷/暖/中性 · 妆效 细闪/大闪/湿光 |
| `lip` | 色系 · 妆效 哑光/缎光/镜面/水光 · 显色度 清透/中等/浓郁 |
| `tools` | 不参与妆效比对 |

**色系是开放维度**：合法取值本质开放（「正红」「砖红」「奶茶色」…），推荐词表只作参考，实际按**语义**比对。这正是匹配案例里「烈焰红唇 vs 橘色嘴唇」的判法——不要因为不在词表里就当作未知。

**妆感浓淡（清透 / 日常 / 浓郁）是派生值**，不单独存，由决定性维度按同一条规则算：

| categoryId | 清透 | 日常 | 浓郁 |
| --- | --- | --- | --- |
| `base` | 遮盖力 清透 | 遮盖力 中等 | 遮盖力 高 **且** 妆效 雾面或持妆持久 |
| `lip` | 显色度 清透 | 显色度 中等 | 显色度 浓郁 **且** 妆效 哑光或镜面 |
| 其余 | 同构，只看浓度维度（`pigmentation` 优先，其次 `coverage`） | | |

判定以决定性维度为准：两者不一致时重算 `intensity`，不改维度。维度未知时不猜浓淡。

## 使用规则

1. 逐件处理妆匣记录，不能先找名为「口红」的条目、只看那一条。
2. 把原始品类、具体类型、产品名称映射到标准品类并**保留原文**。「口红」「唇釉」都进 `lip` 候选组，具体类型仍分别保留——**不等于它们一定能相互替代**。
3. 目标需求与推荐商品同样归一化。目标是「橘色嘴唇」、推荐写「口红」、妆匣写「唇釉」时，先一起检查 `lip` 候选，再按颜色、质地与妆效决定可否复用。区域名「嘴唇」不是品类匹配键。
4. 清单「用什么达成」列统一写「标准品类（具体类型）」，如「唇妆（口红）」。一个妆效需多个品类时逐个列出。
5. 未知或复合品类**保留为待归类候选，不丢弃**。仅写「粉饼」时需按实际用途区分底妆或定妆；眼唇两用、综合彩盘可对应多个品类，但跨部位用途必须有产品适用说明支持。不能为匹配成功直接抹平功能差异。
6. 不依赖显示文字完全相等来筛选；内部先匹配标准品类，再检索具体 SKU 并比对目标能力。
7. 闭集外的取值保留原文，但**不参与妆效比对**；缺失＝未知，不编造。
