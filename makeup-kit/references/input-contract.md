# 妆匣输入约定

本约定描述匹配需要的信息。实际存储格式、字段名与调用接口由应用提供：**妆匣存在应用的存储里，用户在自己的妆匣 Tab 录入，Agent 通过 `kit_list_products` 只读访问**。本文件不定义接口，也不假定数据库或文件格式。

## 读取上下文

每次读取后要能回答三件事：

- **来源**：本轮 `kit_list_products` 的实际返回。没有调用就没有来源，不能声称已读取。
- **可用性**：`ok` / `empty` / `read-failed` 三态，含义与措辞见 `SKILL.md` 的读取表。**「成功读取但空」与「没取得数据」必须分开。**
- **范围**：`scope.total` 与 `scope.returned`；传了 `categoryId` 时返回的是筛选后的子集。只有确认覆盖相关记录，才能判断「妆匣未记录某品类」；部分数据只能说明已读部分的结果。

用户范围**由应用提供**（运行时注入的身份），不能根据对话文字或搜索结果切换用户。

## 用户录入字段

| 信息 | 作用与未知处理 |
| --- | --- |
| 品类 | 映射到标准品类，再筛选同品类与同功能候选；不依据名称字面是否相等 |
| 品牌 | 与品类、色号一起作为检索线索 |
| 色号 | 有色产品的色号，盘类可填盘号；没有色号写「不适用」，不知道留空 |

**必填只有品类与品牌**，色号对部分品类（工具等）本来就不适用。产品名、系列、颜色、妆效、质地由系统在录入时判断并填好；用户主动提供的其他信息可以使用，但不扩展固定录入要求。

**持有证据**来自妆匣记录与用户声明；**商品属性证据**来自检索。两者不能相互代替。

## 特点（属性）

每件记录带 `attributes` 与 `attributeSources`：

- `attributes` 里的取值按 [品类映射](categories.md) 的维度表填写。**为空表示未知**，不是「没有该属性」。
- `intensity`（妆感浓淡）是服务端按决定性维度算好的派生值，直接用。
- `attributeSources` 说明每条特点有多可信：`user`（用户填或改过）、`model-inferred`（**录入时模型按产品身份推断的线索**）、`search-verified`（预设策展时离线核实过）。

`model-inferred` 只用于缩小检索范围。**判定复用所依据的决定性属性仍然要按 `SKILL.md` 的核对流程检索一次**；核实结果只在本轮答案里体现，不写回妆匣。

## 三项信息可能对应多个候选

研究时判断哪些属性已查明、是否足以支持本次妆效对比；**不能为了输出完整 SKU 擅自指定某个版本**。只要候选在本次决定性属性上一致、足以判断，就可作出结论；完整身份未知不自动等于匹配待确认。仅在没有已确定的不符、且关键属性歧义可能改变结论时标 `❔`，不要求用户补填一整套商品字段。

比较顺序：**已知妆匣产品 → 用户诉求 → 由诉求推导的产品需求 → 是否满足**。只比较影响本次诉求的能力，不增加用户没有提出的要求。
