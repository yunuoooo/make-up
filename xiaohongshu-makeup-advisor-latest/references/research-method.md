# 研究与推荐方法

## 1. 建立妆容指纹

按实际相关性检查这些维度，不必机械地逐项输出：

| 维度 | 观察重点 |
| --- | --- |
| 底妆 | 哑光/奶油/水光，遮瑕度，厚薄，是否保留皮肤纹理，定妆范围 |
| 眉毛 | 粗细、弧度、毛流、颜色、眉峰和眉尾走向 |
| 眼影 | 主色、冷暖、明度、饱和度、晕染边界、眼皮与下眼睑的落点 |
| 眼线与睫毛 | 线条粗细和上扬度，内外眼线，睫毛束感、密度、长度与卷翘 |
| 腮红 | 色相、明度、位置、范围、形状，以及与修容的关系 |
| 修容与高光 | 骨相方向、明暗对比、光泽颗粒和高光位置 |
| 唇妆 | 色相、冷暖、明度、饱和度、透明度、边界、哑光/镜面质感 |
| 整体 | 对比度、色彩数量、视觉重心、留白、氛围、镜头/现实适用度 |

把每个核心视觉特征写成能挑选产品的规格。例如，"低饱和灰粉眼妆"应转换为"偏灰、不发橙、低到中显色度、易叠加的冷粉/灰棕盘"，而不是直接跳到品牌名。

真实妆容的目标规格来自本轮有效证据与用户实际约束。解释匹配机制的假设例子只用于验证逻辑，不给风格设置默认色彩，也不因妆匣里有某色就倒推目标需要该色。用户要求并排测试不同颜色时，分别标成假设场景，并说明它们与研究得到的风格方案的关系。

输出时把妆容指纹压进特点与选品拆解表，不再另写一套逐部位总结。每个可观察特点只保留一行；整体风格只在表前用一句话概括，变体与争议集中说明。

研究记录为每个采用的特点保留四项：特点；实际来源（笔记 ID、字幕时间戳或检查过的图片及范围）；核心、条件或增强项的判断理由；对应清单行与实现路线。这是本轮研究的工作记录，**不增加用户妆匣录入字段**。

输出前逐项核对这四项。有证据支持的核心明暗塑形、睫毛结构等必须在必要表中有对应路线；核心特点缺行时先补齐再输出，SKU 资料不足时先定向检索，仍无法查明则保留目标规格并说明证据限制，不冒充已验证商品、不删掉妆效。条件或增强项须写触发条件，不能只凭商品类别判断可选。用户问为什么时，能回到实际读取的来源与判断理由；不能用一次 SKU 颜色检索证明整个风格需要该颜色。样本只覆盖某一分支时，说明分支和证据范围，不扩展成所有同名妆容的必需项。

**目标特点用妆匣与推荐共用的词表**：妆效、遮盖力、妆感浓淡这类描述按 [标准品类与特点词表](../../makeup-kit/references/categories.md) 的维度与取值写（运行时以 `lib/kit/attributes.ts` 为准）。需求侧说「浓郁」而能力侧记「遮盖力高」时，两侧对不上，复用判断就退回自由发挥。

## 2. 设计站内搜索

从用户用词生成少量互补查询。先用一个主查询，只有证据不足时才追加，避免重复计费：

- 风格主查询：`<风格名> 妆容`、`<风格名> 教程`。
- **SKU 主查询**：优先 `<风格名> 选品推荐`。风格名沿用用户用词，不机械重复添加"妆容"。图文用正文与清晰图片找品牌、产品线和色号；视频用字幕找明确口述的产品与用法。**不要重复读同一篇笔记**，已经读过详情的条目直接复用。
- **SKU 补搜**：仍无可识别产品且结果可能改变选品时，最多从 `<风格名> 彩妆好物`、`<风格名> 产品推荐教程`、`<风格名> 必吃榜` 中选一个补搜，**不依次执行全部查询**。跨图文与视频取得 1–3 个足以影响决策的产品身份后停止，不因缺少口播 SKU 而继续搜索。单次试验只说明该风格本轮有用，不保证对所有风格都更好。
- 对尚未覆盖、且可能影响决策的具体品类，可把品类加入当前查询，如 `<风格名> 选品推荐 腮红`；这属于上述一次补搜预算，不另起无限的逐品类搜索。纯音乐歌词、开场白和"这支/这一盘"即使有字幕，也不算有效口播产品证据。
- 适配查询：加入肤质、肤色、单眼皮/双眼皮、眼镜、通勤、婚礼、上镜等真正相关的条件。
- 别名查询：只加入从结果中确认存在的常用别称，不自行发明趋势名称。

图文搜索结果应覆盖教程、近距离妆效、产品清单或试色，不要只看标题相似的成片；视频字幕应补足步骤、顺序、用量和口述产品线索。当前工作流**不读取评论区**，所以不能声称评论支持了任何产品或结论。

搜索结果每条只有标题、作者、互动数和一段约 60 字的**截断预览**：预览只用来筛掉明显不相关的条目，**不能当正文**，判断特征必须靠打开后的正文和画面。

第一轮用于建立通用妆容指纹，不因缺少个人条件而暂停。第二轮复用首轮结论，只对肤质、肤色、预算、发色、假睫毛接受度或风格分支会改变的品类追加搜索；不要机械重读所有通用笔记。

## 3. 评估证据

优先级从高到低：

1. 多位独立创作者反复出现、且图文画面或带时间戳的视频步骤能验证的特征。
2. 有清晰上脸、试色、使用步骤、产品标注或完整口述产品名的单篇教程。
3. 只有成片、标题、无视觉支持的口头断言或字幕中无法解析指代对象的笔记。
4. 明显商业合作、店铺带货或无法确认产品身份的内容。

至少记录标题、创作者、笔记类型、可见日期、**站内复搜关键词**、支持的特征、实际读取耗时和是否疑似商业内容；视频证据再记录 `[MM:SS]` 时间戳和字幕是否完整。两位以上独立创作者重复出现可称为"常见特征"；单篇观点应标为"个别笔记做法"。点赞量只表示传播度，不证明产品适合用户。

另记实际检查范围：详情是否取得、正文或字幕是否读到、图片检查了哪些张及是否完整加载。**仅取得视频详情不等于看过视频或读到步骤**；未播放时称"读取字幕"。求助帖、产品分享、SKU 试色与完整妆容教程分别计数，失败字幕和未显示的图片区域不能作为已学到的证据。

图文与字幕不能互相冒充：字幕不能证明实际色彩、质地、眼线角度或包装；图片不能证明没有写出或说出的具体步骤。字幕里的"这支""这一盘"等指代不补全，ASR 疑似错字不逐字背书。

**产品清单类图文要检查整组 `images`**，不能因正文为空就判定没有产品信息。图片中文字只有在品牌、完整品名和版本／色号确实清晰时才进入具体商品证据；包装相似、OCR 残缺、评论猜测或单独一个数字都不足以补全 SKU。图片直链无法显示时，按标题与创作者在小红书内复搜原帖核对同一组轮播，来源仍标记为本轮工具命中的笔记。

内部研究记录的具体商品证据统一用以下标记，不能把不同强度的线索混写成"小红书同款"。用户正文不展示这些 emoji 标签：

- `🎙️ 视频口播明确提及`：字幕能识别品牌与产品线，必须附 `[MM:SS]` 和视频标题；要称为完整 SKU，还必须确认版本或色号。
- `🎬 视频笔记元数据提及`：产品只出现在视频标题、正文或话题中，不能写成创作者在口播里说过。
- `🖼️ 图文明示同款`：图文正文或清晰图片直接写明产品身份。
- `🧩 特征匹配`：根据已验证妆效规格与用户条件推导的候选，不称为同款。
- `↔️ 替代选项`：为预算、质地或购买便利提供的替代，并说明与原路线的差异。

分别记录产品线、版本与色号的来源。只有产品线被口播提到，或推荐色号不同于口播色号时，来源区写"产品线来自口播；参考色号经官网核实"，原口播色号另列作来源说明。教程只报"裸色口红"时，它支持色彩需求，不能支持系统选出的具体品牌与色号；后者按 `🧩` 特征匹配列出，并附实际核实的产品来源。世界知识可以生成搜索候选，不能代替属性核实，也不算笔记明示产品。

字幕只说"这支／这一盘"、ASR 疑似错字、只有品牌或只有色号时，最多保留为线索，不补全 SKU。单一品牌视频、商业合作和带货内容即使口播完整，也标为弱证据；"被视频提到"不等于"适合用户"或"被最终采用"。

**对口播产品做一次表格覆盖检查**：

1. 身份足够完整且适配用户的，放入对应部位行，研究记录标 `口播首选`。
2. 身份足够完整、但受肤色深浅、预算或场景条件限制的，仍放入对应部位行，研究记录标 `口播条件备选`，「怎么选与怎么做」列写适用条件；默认预算不计入。
3. 身份不完整、明显不适配或证据不可采信的，仅在内部记录未采用原因，不向用户输出这个小节。
4. **已有具体 SKU 经妆匣核对满足目标时，该行采用 `✅` 已有品，口播新品归为"已有品覆盖，无需新增"。** 这优先于前述口播首选/条件备选规则；用户要求额外备选时再保留条件路线。
5. 口播命中、入选和未采用数量只留内部研究记录，不放回复正文，不为展示视频恢复重复购买；也不得在没有合格商品时硬凑 `🎙️`。

## 4. 从特征映射到产品

依次检查：

1. 已通过相邻的 `makeup-kit` 技能用 `kit_list_products` **实际读取当前妆匣**；产品类别是否真的影响该特征，能靠手法或已核实的现有单品完成时，不强行推荐购买。
   妆匣条目、目标需求与推荐商品均按 [共用品类映射](../../makeup-kit/references/categories.md) 归一化；不依赖原始品类字面完全相等。读取失败时说明本轮没取得妆匣数据，购买判断保留为条件候选。
2. 色调、明度、饱和度、显色度、光泽、遮盖力、持妆方式是否匹配。
3. 用户肤质、肤色深浅与冷暖、敏感项、熟练度是否匹配。
4. 预算、购买地区、容量和使用频率是否合理。
5. 色号、版本、名称、在售状态和价格是否能从当前可靠页面确认。
6. 用户是否通过妆匣记录或当轮声明明确确认拥有这件产品；按品类、品牌、色号检索并核对影响本次目标的常规颜色与妆效，证据支持匹配才写 `✅`。用户主动确认的系列信息可用于检索，但不强制补填版本。**同品类或同产品线不等于匹配**。已确认决定性属性不符就明确判不适配；仅在关键未知可能改变结论且没有已确定的不符时用 `❔`。按妆匣技能的范围核对，不展开改变颜色的使用分支；是否补购另判。

"同款"仅用于小红书图文明确展示或写明的产品；视频产品严格区分口播和笔记元数据。"匹配型"表示基于产品属性的推导；"平替"需要同时说明相似点与不可替代的差异。

### 选色

首轮没有用户肤色深浅、冷暖调、原生唇色或底妆试色时，**不给粉底、遮瑕或唇部产品一个绝对精准的色号**：遵守色号待试策略，对用户在产品名后只写"色号待定"，不附候选色系、编号范围或试色说明。不要为它们编造精准编号。

用户已提供肤色条件时按实际条件选色，并用品牌官网或可靠零售页核实目标产品线下实际存在的色号。粉底与基础提亮色的深浅关系、修容与眉色的冷暖、腮红与唇色要能在同一基准下成立。

**未知用户肤色或试色不使新品变成 `❔`**；`❔` 只表示已有品的缺失关键身份或属性会改变复用判断。已确认已有品的决定性颜色不符时，内部保留不适配结论，清单只列核对缺口后选出的新品；用户追问才展开不符依据。

## 5. 特点与选品拆解表

用户可见标题、列名、产品文案、排序与步骤格式统一遵循 [首条回复呈现规范](answer-format.md)。研究记录里的证据标签不直接复制到产品单元格。

- 两表为「核心特点与选品解析」「可选特点与选品解析」，最后一列为「建议产品」。不设必要性列，不另给图例。
- 核心指缺少后会明显失去风格辨识度的妆效；可选指取决于肤质、脸型、眼型、场景或分支的增强项，不等于所有商品必买。
- 全脸底妆在先，其余部位从上到下；跳过无关区域，同一特点只出现一次，多品类或动作共同完成时放同一行。
- 同一产品影响多个部位时，在贡献最大的那一行列出，其他行简短引用，避免重复推荐。「用什么达成」仍写共用品类映射里的标准品类与具体类型，必要时包含工具；「建议产品」写具体商品，两列不重复。
- 粉底行仍分别说明目标妆效、色调／遮盖力／质地，以及统一肤色、保留原生感或控制光泽的作用。精简用户文案不减少这些选品依据。
- 双眼皮贴和美瞳默认可选；基础明暗提亮与额外珠光增强分开判断，不能把核心轮廓一并放进可选。没有可靠的可选项时不为凑表添加商品。
- `✅` 仍只用于已确认持有且可复用的具体产品；`❔` 仍表示会改变复用判断的关键未知；`💰` 表示选择该品需新增购买。每格按这个顺序列出，不改变核对标准。
- 每件单品只写可识别的品牌、产品名与可确认色号，不在产品栏重复用法或画法，不使用「现有眼影」「手边同类腮红」等模糊名称。已知不适配的已有品不展示，内部保留依据；妆匣为空或读取失败时如实用一句话说明，不能宣称现实中一定没有。
- 「色号待试」策略不变，对用户统一写「色号待定」，产品下不附选色方向、范围或试色说明。首轮不为粉底、遮瑕、唇色编造精准编号。
- 备选只在适用条件确有差异时保留，差异写在「怎么选与怎么做」，产品栏只显示身份与「可选」标记，不单写「替代」或拼图证据标签。
- 默认预算只合计去重后确定采用的 `💰` 首选，`✅`、`❔`、条件备选和可选项不混入默认总价。`necessary` / `optional` 商品块字段值保持不变。
- 保留样本支持的核心提亮、轮廓和睫毛结构。能用已有品完成时不恢复重复购买；假睫毛路线只有在自然睫毛条件足够或用户明确接受差异时才替换，不因某品牌可替代而漏掉核心妆效。
- 「视频提及但未采用」、口播数量和工具过程只留内部研究记录。仅在用户主动询问证据时展开；正常回复的「本轮来源」仅列可追溯出处，不给可点链接，也不要自己拼。

## 6. 整体妆效图与视觉证据

默认按这个阅读顺序输出：

1. 用一句话概括整体妆效。
2. 放一张能同时看清整体色彩、质地和视觉重心的完成妆画面。
3. 完整输出"核心特点与选品解析"表，再输出"可选特点与选品解析"表；不在每一行之间插图。

整体图必须来自本次或同一轮研究中实际返回的有效小红书笔记：

- 图片只能是搜索或详情实际返回的那些：详情给图组（图文笔记通常 5–9 张），搜索只给一张封面；视频笔记只有封面帧，它的价值在口播字幕而不是画面。检索不按类型过滤，图文与视频都可能出现在结果里；单张封面可能带文字贴纸、不是完成帧，选图时把这一点算进去。
- 视频的口播字幕随详情一起返回，用 `[MM:SS]` 时间戳引用其中的结论。字幕是自动识别的、可能有错字，按语义转述而不是逐字引用；口播里靠「这一款」「这支」指代的产品**不得**补全成具体商品，要产品名就走商品卡片链路。
- 图片出处统一放在文末「本轮来源」，列笔记标题、创作者和站内复搜关键词；图片旁不放来源信息或工具过程说明（本轮不给可点链接）。图片证明的是可见妆效；只有笔记明确展示或写明时，才把它作为具体产品证据。
- 默认不提供逐部位截图。用户明确要求核验某个局部结论时，才补充能证明该结论的最少量局部截图，并避免把表格内容逐字重复一遍。
- 截图只作为分析所需的视觉证据，不下载或复刻整篇内容。无法取得可靠整体图时明确说明，不换用无关图片。
- 如果用户要求耗时，图文记录每篇详情读取的实际时长；视频分别记录详情、字幕和合计时长。从既有画面重排版式不算一次新的扒取。
