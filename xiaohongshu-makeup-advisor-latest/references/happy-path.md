# 双阶段推荐 Happy Path

## 1. 适用范围

当首次用户用自然语言提出一个妆容或风格目标时使用本流程。研究来源是平台侧已登录的小红书账号及当轮可访问笔记，购买地区默认中国大陆。

首轮不要求参考图，也不要求用户建立或选择个人化妆品库。小红书不可用、用户要求自拍分析或产品库匹配、医疗问题以及交易闭环均不属于本流程。

## 2. 对话顺序

`用户提出风格 → 通用小红书研究 → 第一条通用推荐 → 第二条个性化邀请 → 用户补充信息 → 定向小红书复搜 → 最终个性化推荐`

不要把第一条推荐和第二条邀请合并成一段，也不要把个人信息设为取得首轮结果的前提。

## 3. 第一阶段

### 通用研究

- 从用户原话提取主风格词并立即开始，不先要求用户选择风格分支。
- 搜索风格名、教程、局部画法和产品清单，覆盖完成妆、步骤、清晰局部和产品信息。
- 归纳多位独立创作者的重复特征；把单篇做法标为个别做法。
- 分支差异明显时，首轮只用一两句说明差异，留到第二阶段由用户选择。
- 先得到视觉特征，再转换为产品规格，最后选具体产品。

### 第一条消息

第一条消息必须在用户不继续对话时仍然有用，按以下顺序组织：

1. 用一句话说明整体色彩、质地、视觉重心和浓淡。
2. 能取得可靠画面时，只放一张能代表目标风格的完整妆效图，并标注笔记标题、创作者和链接；默认不放逐部位截图。
3. 先给图例 `💰 需要购买｜✅ 用户已确认拥有`，再输出“必要：特点与选品拆解”表，不设“必要性”列，把核心视觉特点直接映射到实现区域、品类/工具、选品规格、关键画法和“购买结论与具体产品/路线”。
4. 输出“非必要：特点与选品拆解”表，使用同一结构，只放取决于个体条件、场景或分支的增强项；其中 `💰` 只表示选择该增强项时需要购买。
5. 两表先列全脸底妆，再按脸部从上到下排列；同一个特点只出现一次，多种产品或动作共同完成时合并在一行。不要再另列一份重复的逐部位妆容指纹或产品清单。
6. 每个关键品类给 1 个首选；只有存在明确差异时增加 1 个备选。最后一列的每件单品都单独以 `💰` 或 `✅` 开头，并写品牌、完整产品名、版本/色号和证据类型，不得用“现有眼影”“相似口红”等模糊名称代替。
7. 给决定妆效的简短执行顺序和本轮小红书来源。
8. 在消息**最末尾**追加唯一一个 `looktrace-products` 机器可读块，列出本轮每个品类的 `💰` 首选，供系统补全商品图和购买链接：

   ```looktrace-products
   {"version":"looktrace.products.v1","items":[{"category":"粉底液","brand":"兰蔻","name":"菁纯臻颜精华粉底液","shade":"BO-01","section":"necessary"}]}
   ```

   字段只有 `category`／`brand`／`name`／`shade`／`section`：`section` 取 `necessary`（必要表）或 `optional`（非必要表）；色号待试时 `shade` 写空字符串。备选和 `✅` 不进块，每品类最多一条；块里不写价格、链接、图片地址或别的字段。本轮没有 `💰` 首选时不输出这个块。

首轮没有用户现有彩妆清单时，不推断任何单品为 `✅`。具体候选可标 `💰`，其含义是“如果采用这款，需要购买”，不等于断言用户没有同类产品。首轮没有用户肤色深浅、冷暖调、原生唇色或底妆试色时，不给粉底、遮瑕或唇部产品一个绝对精准的色号；在产品名后明确写“色号待试”，并给色调、深浅范围、质地和现场试色方法。

## 4. 第二条个性化邀请

在第一条推荐发送完成后，单独邀请用户补充：

- 肤质
- 肤色深浅和冷暖调
- 总预算
- 发色
- 是否接受假睫毛
- 具体风格分支，例如清冷、通勤、甜酷或辣妹
- 敏感成分或其他避雷项
- 愿意继续使用的现有彩妆：品牌、完整品名、版本/色号；不知道时可提供清晰包装照片或跳过

明确购买地区默认中国大陆，并允许用户对任何未知字段回答“不知道”。这条消息只说明补充信息能如何提高匹配度，不重复通用推荐。

若用户在初始请求中已经提供其中部分信息，保留已知值，不重复询问。

## 5. 第二阶段

结构化用户条件并只重搜受影响的品类：

| 用户条件 | 主要影响 | 搜索方向示例 |
| --- | --- | --- |
| 具体风格 | 色彩浓淡、氛围和眼尾走向 | `<具体风格> <妆容名> 眼妆 产品` |
| 肤质 | 底妆质地、遮盖力、定妆与持妆 | `<妆容名> <肤质> 底妆` |
| 肤色深浅和冷暖调 | 底妆、修容、眼影、腮红和唇色 | `<肤色条件> <目标色系> 腮红` |
| 总预算 | 价格带和跨品类预算分配 | `<妆容名> 全套 <预算>` |
| 发色 | 眉笔和染眉色 | `<发色> <目标眉色>` |
| 假睫毛接受度 | 假睫毛或睫毛膏实现路线 | `<妆容名> 眼尾假睫毛` |
| 敏感或避雷项 | 排除配方、质地或使用部位 | 按具体条件筛选 |
| 现有彩妆 | 判断能否复用，并把对应购买候选改为 `✅` | 按完整品名核对色调、质地、版本和色号 |

复用首轮已经确认的妆容指纹，不机械重复全部通用研究。先逐件核对用户现有彩妆与目标规格是否匹配：匹配时写出该具体产品并标 `✅`；不匹配且确需新增时才标 `💰`。复核具体商品的版本、色号、质地、价格带和在售信息，并保留“小红书同款、特征匹配、替代选项”的证据标签。

## 6. 最终个性化推荐

最终消息依次包含：

1. 简短列出已采用的肤质、肤色、预算、发色、假睫毛偏好和风格分支。
2. 说明相对通用版改变了哪些色调、质地、实现路线或优先级，以及原因。
3. 沿用“必要”与“非必要”两个独立 section；各自用从全脸底妆到下巴的顺序给出区域、目标特点、实现品类/工具、选品与画法，以及“购买结论与具体产品/路线”，不再单设“必要性”列。每件单品分别以 `💰` 或 `✅` 开头，并写品牌、完整产品名、版本/色号和证据类型。
4. 关键品类给 1 个首选；需要时给 1 个具有明确差异的备选。
5. 给出新增购买预计价格区间，只合计 `💰` 项；从 `💰` 项中列优先购买和可以后补的品类，`✅` 项不重复计价。
6. 用简短步骤说明决定妆效的动作。
7. 列出本轮有效来源，并标注共识、个别做法和产品证据类型。
8. 在消息最末尾追加唯一一个 `looktrace-products` 块，规则同第一阶段：只列 `💰` 首选，每品类最多一条，不带价格和链接。

推荐理由必须同时关联目标妆效与用户条件，不能只复述商品卖点。

## 7. 必选与可选

分别判断“妆效是否必要”和“某类商品是否必要”：

- 必选妆效：缺少后会明显失去目标妆容辨识度。
- 可选妆效：取决于肤质、脸型、眼型、场景或用户选择的分支。
- 实现路线：达到同一妆效可使用不同商品或手法，因此必选妆效不等于必须购买指定品类或品牌。
- 购买标记：`💰`/`✅` 只表达当前选中具体单品的购买状态，不替代“必要/非必要”对妆效的分类。

例如猫眼分支中的“眼尾渐长成束”可以是必选妆效。首轮可把假睫毛列为优先路线，但是否把假睫毛商品列为最终必选，应结合样本证据、用户自然睫毛条件和第二阶段的接受度。双眼皮贴和美瞳默认是条件项。

输出时把两类结果拆成“必要”和“非必要”两个 section，不用“必要性”列重复标记。分类的对象优先是视觉特点；具体商品是实现路线，除非该商品类别本身不可替代。

## 8. 验收清单

- 风格名足以启动，不要求参考图或产品库。
- 先完成通用研究，再交付独立可用的第一条推荐。
- 第一条包含一句整体妆效、一张可靠的整体妆效图、必要与非必要两张拆解表、产品候选和来源。
- 两张拆解表不设“必要性”列，按全脸底妆在先、其余部位从上到下排列；同一特点只出现一次；表前有 `💰`/`✅` 图例。
- 每件推荐单品都有独立购买标记和可识别的品牌、完整产品名、版本/色号；没有“用现有眼影”一类模糊路线。
- 个性化邀请是第二条独立消息，不重复首轮内容。
- 邀请覆盖肤质、肤色深浅与冷暖调、总预算、发色、假睫毛接受度、具体风格和可选的现有彩妆明细。
- 明确默认地区并允许回答“不知道”。
- 第二轮把个人条件转换为定向搜索条件，不重复整个第一轮。
- 最终推荐说明相对通用版的调整，并把产品理由同时连接到妆效和个人条件。
- 每个关键品类默认 1 个首选，仅在存在明确差异时增加 1 个备选。
- 最终结果只合计 `💰` 项的新增购买预算，并包含购买优先级、执行顺序和本轮来源。
- 首轮和最终推荐的消息末尾都有 `looktrace-products` 块：只列 `💰` 首选，每品类最多一条，只有五个规定字段，不含链接和价格。
